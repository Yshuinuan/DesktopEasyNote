## 3. 应用数据目录（R3 / R16）

- 根目录：`%LOCALAPPDATA%\DesktopEasyNote`（**R16 / v1.6 起**；旧版本为 `%LOCALAPPDATA%\桌面旁白记录器`）
  - `LOCALAPPDATA` 缺失 → 回退 `%APPDATA%`；再缺失 → 回退当前工作目录。回退会写 WARN 日志，不崩溃。
  - 旧根按同样的回退规则推导：`<同一基目录>\桌面旁白记录器`（即 `%LOCALAPPDATA%\桌面旁白记录器`）。
- 子目录与文件：

| 路径 | 用途 |
|---|---|
| `<root>/data/YYYY-MM-DD.md` | 当天记录（一天一个文件，UTF-8） |
| `<root>/output/YYYY-MM-DD.md` | 当天旁白导出（P2 写入） |
| `<root>/logs/app-YYYY-MM-DD.log` | 文件日志（按本地日期分文件） |
| `<root>/config.json` | 配置（apikey / baseURL / model） |

- 启动时确保根目录与 `data/`、`output/`、`logs/` 存在；失败只写日志，不弹窗、不崩溃。
- **业务代码不得硬编码路径**，一律用 `paths::get()`（见 §9.1）。
- `YYYY-MM-DD` 一律是「这天开始的日期」，按 06:00 跨天口径（见 §4）。

### 3.1 一次性迁移（R16，v1.6；只复制、不删除）

- **触发**（每次启动检查）：新根**既无 `config.json` 也无 `data/`**，且旧根存在（旧根不是目录视为不存在）。
- **迁移内容**：`config.json`、`data/**`、`output/**`；**不迁移 `logs/`**；旧根其它文件也不复制。
- **步骤**：创建新根与子目录 → **逐文件复制（只复制、不移动）** → 每个文件校验 `size` + `SHA-256`（源/目标一致）。
- **成功**：本次启动使用新根；**不删除任何旧数据**——旧根 `config.json`/`data/`/`output/`/`logs/` 全部原样保留，由用户确认新版正常后自行清理；日志写一条 INFO（文件数、总字节、校验结果、旧根保留说明）。
- **失败**（复制或任一文件校验不一致）：回滚本次写进新根的不完整副本（新根既有文件不覆盖、不删除）→ 写 ERROR → **本次启动继续使用旧根**（不丢数据），下次启动重试。
- **新根已有数据**：不迁移、不覆盖，本次使用新根；日志写一条 INFO 说明「使用新根，旧根保留」。
- **旧根不存在**：正常以新根运行，不报错。
- 迁移只做一次：新根有数据后不再复制。
- 实现位置：迁移判断与复制在 `paths::init()` 内完成（早于日志初始化），结果由 `paths::migration_report()` 取回、`lib.rs` 在日志就绪后输出 INFO/ERROR；业务代码仍只用 `paths::get()`，无需感知迁移。

## 4. 一天的定义与记录行格式（R9）

### 4.1 跨天（`day.rs`）
- 一天 = 本地时间当天 06:00 → 次日 06:00；00:00–05:59 的记录归**前一天**。
- 例：11-15 01:50 写 → `day_key = "2026-11-14"`。
- 全部本地时间（Asia/Shanghai），不用 UTC 判定日期。

### 4.2 行格式
- `HH:MM · 内容 · 心情`；心情**可省略**。
- `HH:MM` 为本地 24 小时制，两位时分；分隔符固定为 `" · "`（空格 + U+00B7 + 空格）。
- 心情 = **默认六词 + 用户自定义词**（任意不超过 8 字的字符串）。默认六词固定顺序：**做成了 / 卡住 / 硬撑 / 走神 / 空转 / 想躲**；自定义词由 `get_moods` 提供，存于 `config.json` 的 `moods`（见 §6/§7）。
- **删除心情只是隐藏**：被隐藏的词仍属于解析用的 known 集合，历史行里的该词仍解析为心情，不会被当成正文；默认六词同样可删（仅隐藏）。
- `Entry.mood` 在文件/JSON 中是字符串（可空）。
- 示例：
  ```
  08:47 · 醒。看了眼时间，又睡了 · 想躲
  11:40 · 泡面，配一个讲时间管理的视频
  16:30 · 便利店，买了冰咖啡，把饭团放回去了 · 走神
  10:00 · 写周报 · 改了三版 · 摸鱼   ← 「摸鱼」为用户自定义词（示例）
  ```

### 4.3 解析规则（`record_line::parse_line`）
1. 去掉首尾空白；空行 → `Err(EmptyLine)`。
2. 按 `" · "` 切段；首段必须严格匹配 `HH:MM`（`^\d{2}:\d{2}$`，0≤时<24，0≤分<60），否则 `Err(InvalidTime)`。
3. 若最后一段 trim 后**整段**命中 known 集合（默认六词 ∪ 用户自定义词，含被隐藏的词）→ 该段是心情；否则最后一段属于内容。
4. 其余段用 `" · "` 拼回内容并 trim；内容为空 → `Err(MissingContent)`。
5. 因此「内容里含 ` · `」可原样往返；「只有时间/时间+心情」视为非法行。

### 4.4 格式化
- `format_line(time, content, mood)` → 有心情 `HH:MM · 内容 · 心情`，无心情 `HH:MM · 内容`。
- 正常行的 `parse_line(format_line(...))` 必须往返一致（P0 单测覆盖）。

### 4.5 标题行
- 当天 `data/YYYY-MM-DD.md` 除记录行外，允许出现 Markdown 标题行：`#`–`######` + 一个空格 + 文字（例 `## 上午`）。
- 标题行不带时间戳，只作文档结构；解析记录时一律跳过，不得计为记录。
- 写入由 P1 规范化（去前导空格、`#`×n + 一个空格 + 文字）。
- 生成引擎（P2）读取时按结构行静默跳过，不计入条数、不进 prompt。

## 5. output/ 约定（P2）

- 旁白写入 `<root>/output/YYYY-MM-DD.md`，文件名与对应 `data/YYYY-MM-DD.md` 同名（用记录那天的日期）。
- 旁白正文 **≤800 字符**（Unicode 字符数，含标点与空格）。
- **不要求正文出现时间戳**；不因正文缺失时间戳、或出现记录外时间戳而触发重试（事实边界由提示词约束）。
- 生成成功才写文件；失败写日志，不打扰用户。
- 提示词唯一来源：`docs/旁白提示词-v3.0.md`；`docs/桌面旁白记录器-策划案.md` §5 为 v1 历史口径，已被 v3.0 取代（策划案原文不改）。

## 6. config.json 与密钥安全（R4 / R14 / R15）

`config.json`（UTF-8 JSON，snake_case）：

```json
{
  "api_key": null,
  "base_url": "https://api.deepseek.com",
  "model": "deepseek-chat",
  "moods": { "custom": [], "hidden": [] },
  "heading_presets": [
    { "level": 2, "text": "问题" },
    { "level": 2, "text": "思路" },
    { "level": 2, "text": "解决" },
    { "level": 2, "text": "复盘" }
  ]
}
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `api_key` | `string \| null` | `null` | 用户填的 DeepSeek key；只在主进程读写 |
| `base_url` | `string` | `https://api.deepseek.com` | P2 调用地址 |
| `model` | `string` | `deepseek-chat` | P2 调用模型 |
| `moods` | `object`（可选） | `{ "custom": [], "hidden": [] }` | R14 自定义心情：`custom` = 用户添加的自定义词（按添加顺序），`hidden` = 被删除（仅隐藏）的词；均由 `moods` 数据层维护 |
| `heading_presets` | `array`（可选） | 级别均为 2 的四条：`问题` / `思路` / `解决` / `复盘` | R15 预设标题：每条 `{ "level": 1–6, "text": string }`；顺序即数组顺序（默认四条在前、新增追加末尾），由 `heading_presets` 数据层维护 |

- `moods` 是**可选字段**：缺失或非法（类型不对/内容坏了）一律按 `custom=[] hidden=[]` 处理，不拖垮整份配置；旧版没有该字段的 `config.json` 可直接加载。
- 只有用户**增删心情**时才写回 `config.json`；写回前完整重读，**不得丢失 `api_key`/`base_url`/`model`**。
- `heading_presets` 是**可选字段**：缺失或非法时数据层使用默认四条；`"heading_presets": []` 是显式空列表（用户把预设全删光），**不回填默认**。
- 只有用户**增删改预设**时才写回 `config.json`；写回前完整重读，**不得丢失 `api_key`/`base_url`/`model`/`moods`**。
- 设置弹窗 v1 只暴露 apikey；baseURL/model 用默认值。
- 前端只能通过 `get_settings` 拿到 `SettingsView { has_api_key, base_url, model }`，**永远拿不到 key 明文**。
- key 不得出现在：日志、前端 console、错误信息、测试、汇报、git 提交。保存失败时页面内显示错误，不崩溃。
- 无 key 的启动（首启或用户没填）→ 自动打开设置弹窗；可关闭，下次启动仍会弹。

## 7. IPC 命令（冻结，不得改名）

所有命令在 `src-tauri/src/lib.rs` 的 `invoke_handler` 注册；前端 `invoke(command, args)` 调用。

| 命令 | 归属 | 参数 | 返回 | 说明 |
|---|---|---|---|---|
| `get_today_document` | P1 | 无 | `Result<Vec<DocLine>, String>` | 读取当天文档（标题行 + 记录行，按文件顺序） |
| `save_today_document` | P1 | `lines: DocLine[]`, `day?: "today" \| "previous"` | `Result<Vec<DocLine>, String>` | 整篇写回；`time=null` 的记录由 Rust 填当前本地时间；`previous` 仅 06:00 跨天用 |
| `get_settings` | P0 | 无 | `SettingsView` | 至少含 `has_api_key: boolean` |
| `save_api_key` | P0 | `key: string` | `void` | 存 key；保存失败 `Promise` reject（字符串） |
| `show_toast` | P0 | `message: string` | `void` | 屏底提示（前端/调试用；P2 用 Rust 函数） |
| `get_moods` | P0 | 无 | `Result<MoodsView, String>` | 心情视图（R14）：`MoodsView { visible, defaults, custom, hidden }`，全部是字符串数组 |
| `add_mood` | P0 | `word: string` | `Result<MoodsView, String>` | 添加自定义心情；判定规则见下 |
| `delete_mood` | P0 | `word: string` | `Result<MoodsView, String>` | 删除心情 = 仅隐藏（默认词同样适用）；历史记录仍能识别为心情 |
| `get_heading_presets` | P0 | 无 | `Result<Vec<HeadingPreset>, String>` | 读取预设标题列表（数组顺序；默认四条在前、新增追加末尾） |
| `add_heading_preset` | P0 | `text: string`, `level: number` | `Result<Vec<HeadingPreset>, String>` | 新增一条（追加到末尾）；规则见下 |
| `update_heading_preset` | P0 | `index: number`（0 起）, `text: string`, `level: number` | `Result<Vec<HeadingPreset>, String>` | 按索引修改一条，位置不变 |
| `delete_heading_preset` | P0 | `index: number`（0 起） | `Result<Vec<HeadingPreset>, String>` | 按索引删除一条 |

- `add_mood` 规则（R14）：trim 后非空；Unicode 字符数 ≤8；不得含 ` · `、换行、制表符；与**可见**心情重名拒绝；命中 `hidden` 即恢复（不删除历史）；可见心情总数上限 20。
- `delete_mood` 规则：只把词加入 `hidden`，**不删除 `custom`**；默认六词同样适用；被隐藏的词仍参与解析（§4.3）。
- 三命令失败时返回可读字符串（前端收到 reject 的字符串，原地展示），成功返回最新 `MoodsView`，菜单据此整体刷新。
- `HeadingPreset` 形状：`{ "level": 1–6, "text": string }`（见 §10.3）；四条命令成功时均返回**操作后的完整列表**，前端整体刷新。
- 预设标题校验与规则（R15）：`text` trim 后非空、Unicode 字符数 ≤20、不得含换行/制表符/` · `；`level` 限 1–6；同一 `text` 不得重复（不论级别）；总数上限 20；顺序 = 数组顺序（默认四条在前、新增追加末尾）；索引越界、校验失败、写盘失败均 reject 可读字符串。
- 预设标题的**插入行为由 P1 实现**（选中后向文档写入对应级别的 `#` 标题），P0 只提供数据层与命令。

`DocLine` 形状（serde `tag = "kind"`、`rename_all = "snake_case"`）：

- `{ "kind": "heading", "level": 1..=6, "text": string }`
- `{ "kind": "entry", "time": string | null, "content": string, "mood": string | null }`（`mood` 为任意心情词字符串，见 §10.3）

- Rust 侧命令名与前端调用名必须一致（`#[tauri::command] fn get_today_document()` ↔ `invoke("get_today_document")`）。
- P1 可以在 `records.rs` 内补充内部辅助函数/参数（如 `AppHandle` 注入），但**命令名、前端参数名、返回结构不得变**。
- 失败返回 `Result<_, String>`（前端收到 reject 的字符串），错误文案面向用户可读。

## 9. Rust 内部 API（P1/P2 按此调用）

### 9.1 路径：`crate::paths`
```rust
pub struct AppPaths {
    pub root: PathBuf,
    pub data_dir: PathBuf,
    pub output_dir: PathBuf,
    pub logs_dir: PathBuf,
    pub config_file: PathBuf,
}
impl AppPaths {
    pub fn data_file(&self, day_key: &str) -> PathBuf;   // data/YYYY-MM-DD.md
    pub fn output_file(&self, day_key: &str) -> PathBuf; // output/YYYY-MM-DD.md
}
```

### 10.3 共享 TS 类型：`src/types.ts`
```ts
export type Mood = string; // 任意心情词：默认六词或用户自定义词（与 Rust serde 输出一致）
export interface MoodsView { visible: string[]; defaults: string[]; custom: string[]; hidden: string[] }
export interface HeadingPreset { level: number; text: string } // 预设标题（level 1–6）
export interface Entry { time: string; content: string; mood: Mood | null }
export interface SettingsView { has_api_key: boolean; base_url: string; model: string }
```
与 Rust `record_line::Entry`、`moods::MoodsView`、`heading_presets::HeadingPreset`、`config::SettingsView` 的 serde 输出一一对应；JSON 字段名必须一致。

- `MoodsView` 字段语义（R14）：
  - `visible`：菜单顺序，默认六词在前（已排除被隐藏的），自定义词按添加顺序；
  - `defaults`：默认六词（固定顺序，含被隐藏的）；
  - `custom`：用户自定义词（按添加顺序，含被隐藏的）；
  - `hidden`：被删除（仅隐藏）的词，可能包含默认词。
- 默认六词（做成了/卡住/硬撑/走神/空转/想躲）只是初始值，**`MOODS` 不再是唯一来源**：前端不得硬编码六动词；右键菜单必须以 `get_moods()`（`visible`）为准，增删心情后用命令返回的新 `MoodsView` 整体刷新。
- `HeadingPreset`（R15）：`{ level: 1–6, text: string }`；数组顺序即展示顺序（默认四条「问题/思路/解决/复盘」在前、新增追加末尾）。列表来自 `get_heading_presets()`，增删改命令均返回完整数组；选中预设后向文档插入对应级别 `#` 标题的行为由 P1 实现。
- `DocLine`（记录页文档行类型）：目前由 P1 定义在 `src/records/index.ts` 内，未放入 `src/types.ts`；形状与 §7 表下一致：
  `{ kind: "heading"; level: 1..=6; text: string }` 或 `{ kind: "entry"; time: string | null; content: string; mood: Mood | null }`。
- 说明：`Mood` 仍来自 `src/types.ts`；后续若要把 `DocLine` 移入 `src/types.ts`，属可选重构，不影响当前契约。

### 10.4 `src/window.ts`（P0 实现，R13 无边框窗口）

## 11. 窗口、托盘与进程生命周期（R6，P0 责任）

- 主窗口：title「桌面旁白记录器」，默认显示，尺寸 560×720（最小 400×520）。
- 主窗口无系统标题栏（`decorations=false`）；关闭/最小化 → 托盘逻辑不变；退出仍只走托盘「退出」。
- 关闭按钮 → `prevent_close` + 隐藏到托盘；最小化 → 隐藏到托盘；进程保留。
- 托盘：tooltip「桌面旁白记录器」；左键 → 显示并聚焦主窗口；右键菜单固定两项「设置key」「退出」（debug 构建多一项「测试提示（调试）」）。
- 托盘「退出」→ `app.exit(0)`，真正退出。
- 单实例：`tauri-plugin-single-instance`；第二次启动只唤起已有主窗口，不出现第二个托盘。
- 屏底提示窗口：label `toast`，从启动起常驻（透明/置顶/点击穿透/不进任务栏/不抢焦点），位置由 Rust 定在主显示器工作区底部居中。
